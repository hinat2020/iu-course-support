# iU 履修サポート v0.1

iUの2026年度入学・1年生後期を対象に、履修登録に必要な判断と確認を支援するReact Webアプリです。アプリ全体を「1年後期 履修登録」と、4年間の履修計画を扱う「卒業設計」の2系統に分けています。卒業設計では公式学生便覧のカリキュラムを使い、8学期へ将来の履修予定を配置できます。

このアプリは非公式ツールです。履修登録を自動化せず、UNIPAや大学公式システムとは接続しません。最終的な履修登録内容、申込期限、抽選結果、教員、教室などは、必ずUNIPAと大学公式資料で確認してください。

## 対象

- 対応年度: 2026年度
- 対象学生: 2026年度入学・1年生後期
- 年度データ更新日: 2026-09-11（このリポジトリ内データの更新日であり、大学資料の発行日ではありません）

## できること

- 初回セットアップと1年前期履修状況の記録
- A〜Eモデルと通常／Advancedから後期必修8科目・14単位の時間割を生成
- 通常候補7科目の時間割重複、年間CAP、卒業要件への寄与を確認
- 通常抽選の申込状況、希望枠、結果、UNIPA確認状態を記録
- イノベーション特講・イノベーション技法を通常抽選と分離して管理
- Homeで未確認事項を確認し、最終履修確認画面でUNIPA確認を補助
- アプリ全体のHomeから「1年後期 履修登録」と「卒業設計」を選択
- 公式学生便覧の科目を検索し、卒業までの8学期へ将来の履修予定を追加・移動・削除
- 科目概要、現在状態、時間割・CAP・抽選情報と、PDFに照合できた2026年度公式シラバスを科目詳細で確認
- 設定変更と、確認付きの全データ初期化

## できないこと

- UNIPAへの自動ログイン
- 履修登録の自動送信
- 抽選申込の自動送信
- 抽選結果の自動取得
- 大学アカウント認証や大学公式システムとの連携
- 複数端末同期、通知、分析、広告
- PDFから各courseIdへ一意に照合できなかったシラバスや、未確定大学情報の推測
- 卒業可否の最終判定、前提科目・CAPによる配置の強制制限、自動履修案

## データ保存とプライバシー

入力内容はバックエンドへ送らず、利用中のブラウザのLocalStorageだけに保存します。保存キーは `iu-course-support:v1` です。ブラウザやサイトデータを削除すると復元できません。別ブラウザ・別端末とは同期されません。

状態更新はReact Context + `useReducer` だけを通し、UIからLocalStorageを直接変更しません。現行 `schemaVersion` は5です。卒業計画は `graduationPlan.entries` に将来予定だけを保存し、1年前期の修得実績と1年後期の状態は既存stateから導出します。v1〜v4の保存データはmigrationでv5へ安全に移行します。LocalStorageキーは従来どおりです。

## ローカル起動

正式なpackage managerはnpmです。`package-lock.json` を唯一のlockfileとして使用し、ローカルとCIで `npm ci` を共通利用できることを優先しています。Node.js 22以上を使用してください。

```bash
npm ci
npm run dev
```

検証:

```bash
npm test
npm run lint
npm run build
```

## 画面とルーティング

GitHub Pagesで直接リンクを安全に扱うため `HashRouter` を使用します。

- `#/`: 未設定ならWelcome、初期設定済みならHomeへ転送
- `#/home`: アプリ全体のHome（2つの主要機能の入口）
- `#/registration`: `#/registration/2026-fall` への互換転送
- `#/registration/2026-fall`: 2026年度・1年後期履修登録ダッシュボード
- `#/graduation`: 卒業設計の説明
- `#/graduation/plan`: 8学期ボード、未配置科目検索、計画の追加・移動・削除
- `#/timetable`: 後期必修時間割
- `#/plan`: 後期履修候補
- `#/lottery`: 通常抽選申込記録
- `#/lottery/results`: 通常抽選結果・UNIPA確認
- `#/special`: 特殊科目
- `#/review`: 最終履修確認
- `#/settings`: 設定とデータ初期化
- `#/courses/:courseId`: 科目詳細
- `#/setup/...`: 初回設定・前期入力

モデル・英語トラックが未設定の時間割系ページだけは `#/setup` へ案内します。`setupCompleted` は初回レビューの確定操作でのみtrueになります。設定を変更すると再確認のためfalseへ戻りますが、抽選記録は削除しません。

## 主要な設計

- 大学固有データは `src/data/2026/` へ集約し、Reactコンポーネントや判定関数へ曜日・時限・CAP値を埋め込みません。
- 必修時間割、HomeTask、warning、CAP、衝突、卒業要件進捗、抽選validationは保存せず、現在のAppStateと年度データから毎回導出します。
- イノベーション特講・技法は通常抽選7科目、CAP、7つの卒業要件群へ混ぜません。
- 年度データ不整合はError Boundaryで画面全体の白紙化を防ぎます。エラー時もLocalStorageを削除しません。
- FinalReviewのチェックリストは画面内だけの補助チェックで、大学側の正式確認を意味せず保存しません。
- 卒業設計では、1年前期の `earned` だけを「修得済み」として導出します。1年後期必修は「今学期の必修」、通常抽選科目は当選かつUNIPA登録確認済みの場合だけ「今学期の履修対象」として表示します。検討中・応募済み・結果待ち・落選・当選後未確認は今学期対象単位に含めず、別の状況一覧に表示します。手動の `graduationPlan.entries` は「将来予定」として別集計し、特殊科目の単位はこの集計から除外します。いずれも履修中・単位修得済み・卒業可能と断定する表示ではありません。
- 卒業要件進捗は、公式学生便覧の2025年度以降入学者向け要件と `curriculum.json` を基準に、「修得済み」「今学期を含む」「計画を含む」を分離した試算です。current/plannedは修得済みではなく、表示上の到達は卒業を保証しません。特殊科目と、選択必修超過分の選択科目区分への配分は自動判定しません。
- 卒業設計の「計画チェック」は、卒業要件、CAP、前提科目、配当年次・学期、未確認事項をまとめて確認するderived表示です。警告が0件でも卒業を保証せず、特殊科目など一部の試算外事項があるため、最新の学生便覧・UNIPA等を必ず確認してください。
- 「不足を埋める科目を探す」は、2026年度公式curriculumの条件に一致する未使用科目を列挙する機能です。おすすめ・順位付け・自動履修計画ではありません。配当年次、学期、前提科目、CAPのpreviewは計画補助であり、将来年度の実際の開講や履修可否を保証しません。
- 職業専門科目の「選択」区分は、一般配置できる直接候補を現行curriculumから確認できません。選択必修の超過単位は選択科目へ算入できる公式記載がありますが、区分別配分をアプリで自動決定せず、特殊科目の扱いとあわせて公式確認を案内します。

## 2026年度データ更新ガイド

| ファイル | 役割 |
| --- | --- |
| `metadata.json` | 対応年度、対象学生、このアプリ内データの更新日 |
| `courses.json` | 曜日・時限を持たない科目マスタ |
| `timetable.json` | モデル・英語トラック別の開講情報、特殊日程 |
| `registration-rules.json` | 年間CAPなどの履修登録ルール |
| `graduation-requirements.json` | 総単位、必修、選択必修7群、選択科目区分、超過単位の公式卒業要件 |
| `lottery.json` | 通常抽選7科目と通常抽選日程 |
| `special-courses.json` | 特殊抽選日程、特講クラス、技法ミニ講座・イベント |
| `first-semester-setup.json` | 1年前期入力の対象科目ID |
| `course-planning.json` | 後期の通常履修候補ID |
| `syllabus.json` | 公式PDFからcourseIdへ一意に照合できた科目のシラバス本文・メタデータ |
| `syllabus-audit.json` | course master全件のmatched / unmatched / ambiguous照合記録 |
| `curriculum.json` | 2026年度学生便覧の授業科目一覧・配当年次・学期・単位・要件記号・前提科目 |

`syllabus.json` は `2026shirabasu.pdf` の表を項目単位で抽出し、科目名・学期・単位数・科目コードをcourse masterと照合した静的データです。旧名称併記、a/b、ローマ数字を含む名称は、似ているという理由だけでは紐付けません。シラバス値は閲覧専用で、CAP・時間割・抽選・卒業要件の判定値には利用しません。シラバスを更新する場合は公式PDFを唯一の根拠とし、照合範囲をレビューしてから `syllabus.json` と `syllabus-audit.json` を更新してください。

JSONを変更したら `npm test` でID重複、参照整合性、全モデルの時間割生成、抽選・特殊科目の分離、シラバス構造を確認してください。大学固有ルールはdomainロジックへ直接追加せず、年度データから引数として渡します。不明な値は推測せず、`null`、`未設定`、またはTODOとして残します。

### 日程境界

通常抽選・特殊抽選の日程判定は案内表示専用で、入力を禁止したり状態を自動変更したりしません。開始・締切時刻は申込期間に含め、締切直後から結果待ちです。通常抽選の確認終了時刻も確認期間に含めます。すべて年度JSONのAsia/Tokyoオフセット付きISO日時を使用します。

## GitHub Pagesへ公開

1. GitHubのRepository Settings → PagesでSourceを「GitHub Actions」に設定します。
2. `main` ブランチへpushします。
3. `.github/workflows/deploy-pages.yml` が `npm ci`、test、lint、buildを通した後、`dist` をPagesへ公開します。

Viteは `base: "./"`、ルーターは `HashRouter` のため、リポジトリ名をコードへ固定せずサブパス配信できます。公開版もLocalStorageのみを使用します。

## 現在の未確定データ

- 社会調査法の卒業要件記号（現在は選択科目・`requirementGroups: []`）
- 教員・教室の完全情報、通常英語の細分クラス
- courseIdへ一意に対応できないイノベーション特講a/bと、通常シラバス項目を持たないイノベーション技法a/bのシラバス
- イノベーション特講2クラスの正確な曜日・時限
- 「忘我LMSによるイノベーション創出」の開催日
- 特殊科目のCAP・卒業要件上の正式な扱い

これらはv0.1でも推測せず、関係画面から公式情報の確認を案内します。
